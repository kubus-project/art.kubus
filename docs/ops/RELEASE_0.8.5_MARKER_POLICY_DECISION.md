## Keep three policy decisions separate

- **Public visibility** controls anonymous map/API/list/OrbitDB/snapshot reads. Migration 108 intentionally gave legacy rows `unreviewed` state while leaving marker public/active fields unchanged ([migration 108, lines 5–8](G:/WorkingDATA/art.kubus/_worktrees/backend-marker-editorial-20261022/migrations/108_editorial_review_state.sql:5)). A public flag or uploader identity does not mean editorial approval.
- **Editorial verification** is an explicit review outcome. The current SEO v1.2 contract says a linked marker route stays accessible and canonical to its artwork, with `index, follow` and no sitemap entry; an unreviewed linked marker does not enrich the artwork page. An independent cultural page requires approval, active/public state, coordinates, a name, and either an 80-character description or a source URL plus Wikidata/OSM identifier ([policy v1.2, lines 39–46 and 73–89](G:/WorkingDATA/art.kubus/_worktrees/backend-marker-editorial-20261022/docs/seo/MARKER_PUBLICATION_SEO_V1.md:39)). Current independent cultural pages qualifying: **0**.
- **SEO/index ownership** is separate from whether a marker appears on the map. The existing linked-marker policy keeps the artwork as canonical owner and linked marker URLs out of the sitemap. No current Google index-coverage measurement or mass canonical/noindex operation was established ([readiness, lines 56–58](G:/WorkingDATA/art.kubus/_worktrees/release-085-preparation-docs/docs/ops/RELEASE_0.8.5_READINESS.md:56)). Therefore the 8,955 map-visible count must not be described as 8,955 URLs to deindex.

The preserved strict-gate WIP is exact HEAD `495ebfa2d350176e30c88bd3b87e8c3a4fde8455`, clean on `codex/marker-editorial-visibility-20261022`; it contains 17 changed files relative to PR #129 head `1e94d5b278df7627fea4fe5f23e993d2b0966517` (20 total against production base `46c9b84`). Its shared public predicate requires approval and is wired into public map/API, OrbitDB/snapshot and SSR marker repository paths. At today’s counts that predicts **0** public marker rows instead of 8,955. Because the SSR repository also uses the strict predicate, linked marker route lookups can become unresolved/404, which conflicts with the v1.2 linked-route contract. The artwork records remain governed by their own publication predicate; the strict marker gate does not itself hide artwork pages. The WIP’s stale Orbit fallback/snapshot behavior is still unqualified and must not be integrated as-is.

## Owner choices

**A. Bounded legacy visibility (recommended).** Preserve public visibility only for a frozen, auditable cohort matching the existing active/public/map-eligible rule at the agreed cutoff. Keep its state explicitly `unreviewed`; do not enrich artwork pages or index independent marker pages from that state. Require approval for new or materially changed markers. Always deny inactive/private markers, rejected/archived records, and markers whose linked artwork is private/inactive. This follows migration 108 and the v1.2 linked-route contract while review proceeds.

**B. Strict approved-only public visibility.** Require explicit approval across map/API, OrbitDB/snapshots and SSR marker reads. With the current cohort, this removes all **8,955** linked marker points/routes from those marker surfaces until individually reviewed. It leaves artwork publication separate and requires no bulk approval. The owner must explicitly accept that public-map and marker-route impact.

**C. Defer and block release.** Keep the current production behavior and keep the strict WIP out of the release until the owner resolves the policy and the selected behavior is qualified end to end.

The data supports A as the least disruptive choice, but only the owner can decide whether continued visibility of explicitly unreviewed legacy records is acceptable. No bulk approval, hiding, deindexing, source integration, or production mutation is authorized by this memo.
